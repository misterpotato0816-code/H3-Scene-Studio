# H3 動画メーカー

> 現在の画面は **H3 Scene Studio** です。最新の変更、テスト、実機で残る音声確認は [2026-09-12監査結果](../docs/AUDIT_2026-09-12.md)、導入は [セットアップ](../docs/SETUP_JA.md) を参照してください。以下は初期アプリの説明を含む開発記録です。

参照画像と日本語の指示から、しゃべる縦型動画を作るアプリです。

ノードを触る必要はありません。**画像を入れて、日本語で指示を書いて、生成を押す**だけです。

---

## これは何か

`<H3_PROJECT_ROOT>` にある完成済みの **H3 Stable統合版**（RTX 3060 と RTX 4070 Ti を併用する
異種GPU構成、実測 217.61秒）を、そのままの生成条件で人間向けの画面から使えるようにしたものです。

- 生成の中身は既存の **H3_HETERO_V1** と同じです。GPU の役割分担も固定値も変えていません
- 既存のファイルは1つも変更していません。このアプリは `<H3_PROJECT_ROOT>\app\` の中だけで完結します
- すでに動いている ComfyUI があっても、終了させたり奪ったりしません

---

## 起動方法

リポジトリ直下の **`RUN_H3.bat`** をダブルクリックしてください（PowerShell からは `app` フォルダで
`python -X utf8 -m h3app.launcher start`）。ブラウザが自動で開きます（開かない場合は http://127.0.0.1:8790/ ）。
既に起動していればブラウザを開くだけで、二重起動はしません。

終了は画面右上の **「H3を終了」** か **`STOP_H3.bat`** です。モデルの解放、H3 が起動した ComfyUI の終了、
設定が有効なら LM Studio の終了、ポートの解放確認まで行います。タブを閉じただけでは終了しません。

> 旧ランチャー `RUN_H3_APP.ps1`（ASCII のみ・UTF-8 BOM 付き）は互換のため残していますが、
> 状態ファイルと安全な終了処理は `RUN_H3.bat` / `STOP_H3.bat` だけが行います。

> 初回の生成では、生成エンジンの起動とモデルの読み込みに数分かかります。2本目以降は速くなります。

## 使い方（5ステップ）

### 1. 画像を入れる

「参照画像」の枠に画像をドラッグ＆ドロップするか、**画像を追加** ボタンで選びます。

| 枠 | 内容 | 必須 |
|---|---|---|
| 画像1 顔メイン | 顔がはっきり分かるカット | **必須** |
| 画像2 上半身 | 服の上半身が分かるカット | 任意 |
| 画像3 補助 | 全身など | 任意 |
| 画像4 補助 | 衣装・小物など | 任意 |

**1枚でも生成できます。** 顔が大きく鮮明に写っているほど、人物が似ます。

### 2. 日本語で指示を書く

「どんな動画にしますか」に、普通の日本語で書きます。

```
笑顔で少し首をかしげる
カメラ目線で自然に話す
落ち着いた雰囲気で
```

**セリフ** 欄に書いた行は、**1行＝1発話としてそのまま**しゃべります。
空にしておくと AI がセリフを考えます。1発話 10〜20文字くらいが安定します。

### 3. 生成を押す

出力時間（既定 5秒）と画面比（既定 縦）を確認して、**生成** を押します。

進行状況が段階表示されます。

```
参照画像を解析しています
キャラクタープロファイルを作成しています
プロンプトを生成しています
H3 conditioning を実行しています
動画を生成しています          ← ここが一番長い
音声と動画を保存しています
完了しました
```

既定設定なら **1本あたり およそ 3分40秒** です。途中で **中止** できます。

### 4. 気に入ったら続きを作る

完成画面の **この動画の続きを作る** を押すと、いまの動画の続きが 5秒ぶん足されます。

```
現在 5 / 15秒   →   現在 10 / 15秒   →   現在 15 / 15秒（最大）
```

15秒に達するとボタンは押せなくなります。続きを作るたびに、**1本につながった動画**として保存し直されます。

構図を変えて別パターンが欲しいときは **同じ設定でもう1本** を押してください。
こちらは画像の解析とプロンプト生成をやり直さないので、その分だけ速く終わります。

### 5. 保存する

**保存先を開く** を押すとエクスプローラーで保存先が開きます。

## ストーリーモード（長い話を複数クリップで作る）

画面上部の **ストーリーモード** に切り替えます。長い文章を場面ごとに自動で分け、順番に生成して、最後に1本へ結合します。

### 使い方

1. **参照画像を入れる**（単発生成と共通）
2. **台本を書く**
   - 長い文章がある場合: 「長文から自動で作る」に貼り付けてボタンを押すと、自動で分割されます
   - 1行ずつ書く場合: 各行の左のチップで **Prompt**（動作・表情・構図）と **Speech**（セリフ）を切り替えます。Speech の行は青く表示されます。上の Prompt / Speech ボタンは、これから追加する行の種類を決めます（初期値は Prompt）
   - `『』` は必須ではありません。チップで区別できれば十分です
3. **動きプリセット**を必要なだけ選ぶ（全セグメント共通で prompt に追加されます）。プリセットだけでも生成できます
4. **セグメント一覧を確認・編集**して「セグメントを保存」
5. **ストーリー開始**

### 停止と再開

- **一時保存して停止**: いま作っているクリップは最後まで完成させてから停止します。その後モデルを解放します
- **再開**: 「保存済みプロジェクト」から選んで開き、**再開** を押すと**次の未生成セグメントから**続きます。生成済みのセグメントは作り直しません
- **クリップが1本完成するたびに自動保存**されるので、途中でクラッシュしてもそこまでの結果は残ります
- **破棄**: プロジェクトフォルダごと削除します（確認ダイアログあり）

### 保存場所

```
app\story_projects\<プロジェクトID>\
  project.json    設定・進捗・クリップ一覧
  segments.json   セグメント一覧
  clips\          1セグメント＝1クリップ
  frames\         各クリップの末尾フレーム画像
  final\          結合後の完成動画
```

すべて JSON なので、中身を直接見て復旧できます。

### 完成動画

**完成動画を書き出し** を押すと、全クリップを1本に結合します。

### タブを閉じたとき

タブを閉じると停止要求がサーバーに送られます。生成中なら**そのクリップを完成させてから**保存して停止し、モデルを解放します。反応が無い場合も、90秒後にサーバー側の監視が同じ処理を行います。

## モデル解放

画面上部の **モデル解放** ボタンで、GPUメモリ上に残っているモデルを下ろせます。

- GPUメモリ上のモデル（H3本体 / テキストエンコーダ / Video VAE / Audio VAE / 文章生成モデルなど）を解放します。GPU0・GPU1 の両方が対象です
- **ComfyUI 自体は終了しません。** アプリも生成エンジンも起動したままです
- 次回の生成時に、必要なモデルは**自動で再読込**されます（その1回だけ読み込み時間がかかります）
- **CPU GOLD キャッシュや GPU1 TE キャッシュなど、ディスク上のキャッシュファイルは削除しません。**
  解放されるのは VRAM だけです

生成中・続き生成中はボタンが無効になります。画面操作を回避してAPIを直接叩いた場合も、
サーバー側で「生成中のためモデルを解放できません」として拒否します。

確認ダイアログはありません。次回生成時に読み直されるだけの操作のため、1クリックで実行します。

## 詳細設定

初期状態では折りたたまれています。**★推奨** と書かれた値が、実測で検証済みの設定です。

| 項目 | 既定値 | 変えるとどうなるか |
|---|---|---|
| seed | 123456789 | 同じ設定でも絵が変わります。「毎回ランダム」で毎回変えられます |
| steps | 8 | 上げると遅く、下げると崩れます |
| sampler | `res_multistep` | 変更は未検証です |
| scheduler | `simple` | 変更は未検証です |
| 参照画像サイズ | `match` | `max` にすると約90秒遅くなります（目視の画質差は確認されていません） |
| 出力解像度 | 576 × 1024 | 32の倍数、かつ面積 1,032,192px 以下 |
| フレーム数 | 自動 | H3 は `n % 17 == 5` が必要なので、自動計算を推奨します |
| 保存先 | `H3/APP` | 出力ファイル名の先頭になります |

**既定値に戻す** ボタンでいつでも戻せます。

### なぜこの値なのか

これらは `<H3_PROJECT_ROOT>\H3_HETERO_V1_MANIFEST.json` に凍結されている実測値です。
アプリは生成のたびにマニフェストを読み、既定値のままの実行がその内容と一致しているかを
自動で検査します（一致しない場合は生成を始めずにエラーを出します）。

**画面比の「横」「スクエア」は未測定です。** 実測済みなのは「縦（576×1024）」だけです。

## 続き生成の仕組みと上限

- 前の動画の**末尾およそ2.3秒（56フレーム）の映像と音声**を、次の生成の手がかりとして渡しています
- 同時に**参照画像もつなぎ続けています**。末尾だけを頼りにすると数本で人物が崩れるためです
- キャラクターの分析結果（プロファイル）は**使い回し**ます。毎回作り直しません
- 上限は **15秒**（5秒 × 3本）です

つなぐたびに少しずつ絵が変化します。3本つないでも足りない、あるいは変化が気になる場合は、
**同じ設定でもう1本** で新規に作り直すほうがきれいに仕上がります。

## トラブルシューティング

エラーは画面に「止まった場所 / 再試行すべきか / 設定の問題か」の3点で表示されます。
以下は代表的なものです。

| 表示 | 対処 |
|---|---|
| 生成エンジンの起動に失敗しました | `config.json` の `comfy_dir` / `comfy_python` を確認。`_debug\comfy.err` に起動ログがあります |
| ポートが使用中です | `config.json` の `comfy_port`（既定 8411）か `app_port`（既定 8790）を変更。既存プロセスは終了させません |
| 必要なノードが導入されていません | 表示されたノードパックを ComfyUI に導入して再起動してください |
| 必要なGPUが見えていません | 設定 > GPU で動画生成側と別処理側のGPUを確認し、H3が起動したComfyUIで生成する（別の方法で起動したComfyUIは保存済みGPU設定を使いません） |
| モデルファイルが見つかりません | `<COMFYUI_SHARED_MODELS>` の実体と `comfy_paths.yaml` を確認 |
| GPU のメモリが不足しました | 参照画像を減らす / 解像度を 576×1024 に戻す / 参照画像サイズを下げる |
| 文章生成モデルが異常終了しました | もう一度実行。繰り返すなら `config.json` の `vlm.n_ctx` を小さくしてください |
| 応答が止まったため中断しました | 一時的な停止の可能性があります。もう一度実行してください |
| 検証済みの生成設定から外れています | 詳細設定の **既定値に戻す** を押してください |

生成そのものが動かないときは、既存の実測用ランナーが動くかを先に確認すると切り分けが早いです。

```powershell
Set-Location -LiteralPath '<H3_PROJECT_ROOT>'
.\RUN_H3_HETERO_V1.ps1
```

## 変更してはいけないもの

このアプリの速度と品質は、次の4点に依存しています。**触らないでください。**

1. **GPU の役割分担**
   GPU1（RTX 3060）が text/reference conditioning、GPU0（RTX 4070 Ti）が DiT sampling と VAE。
   `SelectCLIPDevice(device="gpu:1")` を外すと 217.61秒の構成ではなくなります

2. **H3-Device-Barrier**（`<H3_PROJECT_ROOT>\custom_nodes\H3-Device-Barrier`）
   文章生成モデルが `torch.cuda.current_device()` を汚したまま H3 に入るのを止めています。
   無いと conditioning でメモリ不足になります

3. **current_device の復元**
   テキストエンコーダのローダーは、必ず復元処理のあとに実行される順序で組まれています

4. **v1 の固定値**
   モデル・テキストエンコーダ・LoRA のファイル名、576×1024 / 124フレーム / 8ステップ /
   `res_multistep` / `simple` / `ref_image_size=match`

`config.json` の `models` を書き換えると、アプリは既定値実行時の整合性検査で止まります。
これは意図した動作です。

> Turbo LoRA について: 既定の `minimax_h3_turbo_v4_step600_ema.safetensors` は、この環境では
> 518キーすべてが読み込みに失敗し、実質的に無効な状態です。**これは意図的です。**
> 217.61秒の実測と目視での品質確認は、まさにその状態で行われました。
> 正しく読み込まれる `_pruned_comfyui` 版に「修正」しないでください。絵が変わります。

## 既知の制限

- 生成中は1本ずつしか実行できません（2本同時に開始しようとすると断られます）
- **中止** は、動画生成の段階ではすぐ効きますが、前半の文章生成（プロファイル作成・プロンプト生成）
  の最中に押した場合はすぐには止まりません。画面は中止済みになりますが、裏の処理はその1回ぶんが
  終わるまで続きます（文章生成モデル側に中断の仕組みが無いためです）。数十秒待ってください
- 保存の最終段階で問題が起きても、動画本体が保存できていれば結果として扱い、警告を表示します。
  再生して問題が無ければそのまま使えます
- 音声にわずかなノイズ感があります。これは H3 側の既知の課題で、このアプリとは別の問題です
- 「横」「スクエア」、および 5秒以外の出力時間は**未測定**です。所要時間も品質も保証されません
- 続き生成の上限は 15秒です
- 参照画像・前クリップの動画は ComfyUI の `input` フォルダに `h3app_` で始まる名前で置かれます。
  不要になったものは手動で削除して構いません

## 開発者向け

| ファイル | 役割 |
|---|---|
| `server.py` | HTTP/SSE サーバ。`--selftest` で ComfyUI 無しにグラフ構築と整合性検査を実行 |
| `h3app/graphs.py` | 3つの API グラフ（プロファイル / プロンプト / 生成）の構築と `assert_v1_parity` |
| `h3app/comfy.py` | 生成エンジンの起動・接続、ノード存在確認、進捗の受信 |
| `h3app/pipeline.py` | 3グラフの実行順、キャッシュ、続き生成 |
| `h3app/projects.py` | プロジェクト状態の保存 |
| `h3app/errors.py` | 失敗の分類と日本語メッセージ |
| `h3app/prompts_bridge.py` | `<H3_PROJECT_ROOT>\build\prompts.py` を読み取り専用で再利用 |
| `web/` | 画面（ビルド不要の素の HTML/CSS/JS） |

```powershell
& '<COMFYUI_DIR>\.venv\Scripts\python.exe' '<H3_PROJECT_ROOT>\app\server.py' --selftest
```

生成されたグラフは `_debug\selftest_*.json` に出力されます。
