# 02. 実行手順

---

## 0. ワークフローを開く

ComfyUI Desktop のワークフロー一覧に **`H3 / H3_phase1_core`** と **`H3 / H3_phase1_full`** が入っています。
（実体：`<COMFYUI_DIR>\user\default\workflows\H3\`）

まずは `H3_phase1_core` から。慣れたら `full` に移ってください。

> **モデル未導入の間は 50 グループのローダーが赤くなります。** これは想定どおりです。
> 20〜40 グループ（VLM でのプロファイル抽出とプロンプト生成）は現状のモデルだけで動きます。

---

## 1. Character Master を作る（人物固定）

### 1-1. 参照画像を用意する

| スロット | 内容 | 推奨 |
|---|---|---|
| ① 顔寄り / FACE | **必須。** 顔がはっきり分かるバストアップ以上 | 長辺 1536px 以上あると有利 |
| ② 上半身 / BUST | 服の上半身が分かるカット | 任意 |
| ③ 全身 / FULL BODY | 全身のシルエット・靴まで | 任意（既定バイパス） |
| ④ 衣装・小物 / OUTFIT | 服だけ・小物だけの参照 | 任意（既定バイパス） |

**1枚しかない場合は ① だけで動きます。** ②③④ はバイパスのままで構いません。

複数視点が1枚にまとまった「キャラクターシート」を ① に入れるのも有効です。

### 1-2. 画像を読み込む

`①顔寄り` の `LoadImage` に画像をドロップ、または choose file から選択。
③④ を使うときは、`LoadImage` と**その直下の resize ノードの両方**を選んで **Ctrl+B**（バイパス解除）。

> 片方だけ解除すると壊れます。必ずペアで。

### 1-3. 参照サイズについて

resize ノードの `scale_to_length`（長辺 px）で調整します。既定は 1536 / 1152 / 1152 / 896。

- **上げると**：人物の同一性が上がる。ただし参照トークンが毎ステップ乗るので遅くなる
- **下げると**：速くなるが顔が似なくなる

`ref_image_size = max` は短辺 2048px までを使いますが、**元画像より拡大はしません**。
参照が小さいと `max` にしても効果が頭打ちになります。
高解像度の参照ほど有利、ただし必須ではありません。

## 2. Character Profile を抽出する

**20 グループ**だけを実行すれば OK です（`Character Profile` の ShowText ノードを右クリック →
「Run Branch」相当の操作、または全体を Run しても構いません）。

VLM が参照画像を見て、こういう固定フォーマットで書き出します。

```
FACE: Oval face with large almond-shaped dark brown eyes, straight thin eyebrows, ...
HAIR: Jet black, chin-length blunt bob with a straight fringe ending above the eyebrows, ...
BUILD: Slim, narrow shoulders, upright posture ...
SKIN: Fair with a matte finish ...
OUTFIT: Light blue collared short-sleeve shirt with a navy necktie, ...
ACCESSORIES: Mint green over-ear headphones resting around the neck ...
MATERIALS: Crisp cotton weave on the shirt, matte plastic on the headphones ...
COLOR_KEYS: light blue, navy, black, mint green
```

### 使い回し方

- 黄色い `ShowText` は **その場で編集できます**。おかしい記述は直してください
- **気に入ったらテキストをコピーして保存**しておいてください
- 次回以降は `Profile 手動上書き` ノードを **Ctrl+B で有効化**して貼り付ければ、
  VLM の再実行を飛ばせます（`Any Switch` は手動側を優先します）

**同じキャラで複数クリップを作るときは、必ず同じ Profile を使い回してください。**
これが人物一貫性の要です。

## 3. 日本語で指示を書く

**30 グループ**に日本語で書きます。

### ① シーン指示

```
明るいカフェの窓辺。主役の女の子がスマホで自撮りをしながら、
カメラに向かって話しかけている縦型のVlog。アップのカットを多めに。
```

### ② セリフ確定（重要）

**1行 = 1発話。ここに書いた文字列がそのまま `<d>[Japanese] ...</d>` に入ります。**

```
はい、ということでこんにちは！
今日はこのカフェの限定スイーツを食べに来ました。
え、待って？これめちゃくちゃ美味しそうじゃない？
```

- 言い換え・要約・敬体常体の変換は行われません（システムプロンプトの R1 で禁止）
- **空にすると AI がセリフを創作します**
- 1発話 10〜20文字程度が安定します。長い文は割ってください
- 12秒のクリップに入るのは目安で 3〜5発話です

### ③ 前クリップ情報

新規生成のときは既定の `NONE - this is a new clip` のままにしておいてください。

### ④ 避けたい要素

リップシンク崩れ・同一性ドリフト系の既定値が入っています。必要に応じて追記してください。

### 尺（秒）

`PrimitiveFloat` に秒数を入れます。下の `Display Any` に**実際のフレーム数**が出ます。

H3 はフレーム数が `n % 17 == 5` である必要があり、**fps は 24 固定**です。
自動で近い値に切り上げます。

| 秒 | 実フレーム |
|---:|---:|
| 5.2 | 124 |
| 8.0 | 192 |
| 10.2 | 243 |
| 12.3 | 294 |
| 15.1 | 362 |

ノードの tooltip 上の学習済みレンジは 124〜362 フレーム（約 5.2〜15.1 秒）です。
数式ではこの範囲にクランプしています。範囲を変えたい場合は
`フレーム数` ノードの式の `min(362, max(124, ...))` を書き換えてください。

## 4. H3 プロンプトを生成する

**40 グループ**を実行すると、6セクションの英語プロンプトが出ます。

```
subject_definitions
summary
retention_analysis
detailed_description
overall_soundscape
non_diegetic_music
```

黄色い `ShowText` で**直接編集できます**。特に確認したいのは：

| 見るところ | チェック内容 |
|---|---|
| `subject_definitions` | `<Subject 1>` に Profile の外見情報が入っているか |
| `retention_analysis` | 人物が `fully_preserved` になっているか |
| `detailed_description` | `<d>[Japanese] ...</d>` が②のセリフと一字一句同じか |
| `non_diegetic_music` | `N/A` になっているか（BGMは後段で足すため） |

### プロンプトを使い回す

`プロンプト手動入力` を **Ctrl+B** で有効化して貼り付けると、VLM を飛ばして再生成できます。
seed だけ変えて何本か試したいときに有効です。

## 5. 生成する

**50 のモデルが揃っていれば** そのまま Run で生成されます。
`80 Output` に mp4 が保存されます（`output/H3/日付/h3_時刻.mp4`）。

### 起動条件（重要）

このワークフローは **RTX 3060 が見えている状態**で起動した ComfyUI を前提にします。

- `--default-device 0`（4070 Ti を既定にする。**`--cuda-device 0` は不可**、3060 が隠れます）
- `--reserve-vram 1.0`
- `custom_nodes` に **`<H3_PROJECT_ROOT>\custom_nodes`** を含めること
  （`H3-Device-Barrier`。無いと CUDA フェーズ境界が効かず conditioning で OOM します）

`50` グループの `★ GPU1 (RTX 3060) で conditioning` が
text/reference conditioning を 3060 側へ寄せ、DiT sampling と VAE は 4070 Ti で走ります。
実測 217.61 秒（576x1024 / 124f / 8 steps）の構成です。

### 固定すべき値 / 変えてよい値

**固定**（変えると 217.61 秒の実測条件から外れます）

| 項目 | 値 |
|---|---|
| width / height | 576 / 1024 |
| frames | 124（尺 5.0 秒） |
| steps | 8 |
| seed | 123456789 |
| sampler / scheduler | `res_multistep` / `simple` |
| ref_image_size | `match` |
| GPU1 conditioning | `SelectCLIPDevice(gpu:1)` を外さない |
| モデル / TextEnc / LoRA | 50 グループの ★ 印のファイル名 |

**自由に変えてよい**

参照画像、日本語のシーン指示・セリフ・ネガティブ、BGM と音量、
出力ファイル名、`85 Upscale` の ON/OFF、`45 Tail Relay` の ON/OFF

### 解像度を変える場合

`MiniMaxH3ReferenceToVideo` の `width` / `height` を直接編集します。
**v1 の実測は 576x1024 のみ**で、他は未測定です。

| 用途 | width | height | 備考 |
|---|---:|---:|---|
| 高速確認 | 288 | 512 | 厳密に 9:16 |
| **★v1固定** | **576** | **1024** | 厳密に 9:16。217.61 秒の実測条件 |
| 高解像 | 768 | 1344 | 面積上限。9:16 とは 1.6% ずれる。**未測定** |

**seed を固定**すれば、下書きで気に入った構図がほぼそのまま高解像でも出ます。

### 55 Experimental を試す場合

既定では `55 Experimental` グループは全ノードがバイパスされており、
**その状態が v1 厳密一致**です。

グループを右クリック →「Bypass Group Nodes」で有効化すると、
正しく bind する Turbo LoRA と SageAttention 系が入ります。速くなる可能性はありますが
**未測定**で、Turbo LoRA が実際に効くため**同じ seed でも絵が変わります**。
比較するときは seed・プロンプト・参照画像を固定し、1回に1つだけ変えてください。

戻すときは再度バイパスすれば v1 厳密一致に戻ります。

### Turbo LoRA が無い場合

`50` の Turbo LoRA と `55` を全てバイパスし、
`scheduler` ノードの **Steps を 25 前後に上げて**ください。時間はかかりますが生成できます。

## 6. 続きを作る（Continuation / Tail Relay）

### 手順

1. **1本目を普通に生成**して mp4 を保存する
2. その mp4 を ComfyUI の input に置く（`45` の `LoadVideo` から upload でも可）
3. **45 Tail Relay グループのノードを全部選択して Ctrl+B**（バイパス解除）
4. `前クリップの動画` で 1本目の mp4 を選ぶ
5. **`SYS-B: 続き生成` を Ctrl+B で有効化**（これで `[video continuation]` モードになる）
6. **③ 前クリップ情報**を書き換える

   ```
   前クリップ：カフェの外観の前で挨拶をして、ドアに手をかけたところで終わった。
   ```
7. ① シーン指示に「続きで何が起きるか」を書く
8. Run

### tail フレーム数

`tail フレーム数` ノード（既定 56）で変えられます。**固定ではありません。**

H3 は参照動画のフレーム数を `n % 17 == 5` に**切り下げ**ます。
下の値ならロスなしです。

| frames | 秒 | 向き |
|---:|---:|---|
| 39 | 1.63 | ドリフト最小。カットが変わってもよい場合 |
| **56** | **2.33** | **既定・推奨** |
| 73 | 3.04 | 会話の途中でつなぐ場合 |
| 90 | 3.75 | 長回し感を維持したい場合 |

**秒数は自動計算されます**（tail ÷ 24）。音声の切り出し位置も連動します。

### 重要な注意

- **Character Master は接続したままにしてください。**
  `<Video 1>` だけに頼ると数クリップで人物が崩れます。参照画像との併用が前提です
- **Profile も同じものを使ってください**（手動上書きに貼り付けておくのが確実）
- クリップをつなぐたびに少しずつドリフトします。
  4〜5本を超える場合は、途中で「カット割り」（Tail Relay を切って参照画像だけで新規生成）を
  挟むほうが安定します

## 7. 音声を編集する（full のみ）

### BGM を足す

1. `70 Audio` の `BGM ソース`（`LoadAudio`）以下を Ctrl+B で有効化
2. 音源ファイルを選ぶ（`<COMFYUI_SHARED_ROOT>\input\` に置く）
3. `BGM を尺に合わせて切る` の `duration` を動画の秒数に合わせる
4. Run

### 調整する

| ノード | 調整 |
|---|---|
| `BGM 音量 (dB)` | 既定 -14。セリフが埋もれるなら -18、BGMが弱いなら -10 |
| `BGM EQ` | `mid_gain_dB` 既定 -4。声の帯域を BGM 側で凹ませています |
| `AudioMerge` | `add` 推奨。合成後にクリップ防止の正規化が入ります |

**BGM を差し替えるときは、`LoadAudio` を変えて 70 以降だけ再実行**すれば済みます。
H3 の生成をやり直す必要はありません。

### 外部 DAW で仕上げる

`音声のみ書き出し`（`SaveAudioMP3`）を有効化すると音声だけ書き出せます。
DAW で調整したものを `LoadAudio` から戻すこともできます。

## 8. セリフを検証する（full のみ）

`90 検証` の `Apply Whisper` が**生成された音声**を文字起こしします。
30 の「②セリフ確定」と見比べてください。

| Whisper の結果 | 対処 |
|---|---|
| ほぼ一致 | OK |
| 単語が違う | seed を振り直して再生成 |
| 聞き取れない | セリフが長すぎ。1発話 10〜15 文字に割る |
| 英語で出る | `<d>[Japanese]` タグが入っていない。40 のプロンプトを確認 |

Whisper モデルは初回実行時に自動ダウンロードされます（large-v3-turbo で約 1.6GB）。

## トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| 50 のローダーが赤い | モデル未導入。[03_missing.md](03_missing.md) を参照 |
| `Value not in list` エラー | 同上。ファイル名が実物と違う場合はローダーで選び直す |
| 人物が似ない | ① の解像度を上げる / Profile の FACE・HAIR を手で具体的に書き足す / `ref_image_size` が `max` か確認 |
| セリフが変わってしまう | 40 の出力で `<d>[Japanese]` の中身を直接修正して再実行 |
| BGM が大きすぎる | `BGM 音量 (dB)` を下げる。70 以降だけ再実行でよい |
| 続きがつながらない | tail を 73〜90 に増やす / ③前クリップ情報を具体的に書く / SYS-B が有効か確認 |
| VRAM が足りない | 解像度を 576×1024 に下げる / 参照画像のサイズを下げる / 参照枚数を減らす |
| VLM で VRAM を食い潰す | `VLM (Gemma-4)` の `vram_limit` を下げると CPU 実行比率が上がります |
